### コンセプト

| 試行 | しこう | Trying |
| 至高 | しこう | Pursuing |
| 嗜好 | しこう | Savoring |

コピー: 「たくさん考えること。とりあえず試すこと。とにかく上を目指すこと。何より楽しむことを大切に。」
（英訳: “Think, try, pursue, savor — four shades of the same word.”）

### タグライン
- 日本語: 「暗闇の向こうに、光がある。」
- 英語: “Somewhere beyond the darkness, there is light.”

## 3. トップページの現在構成（セクション単位・実際のコピー付き）

現在は**1枚の縦長ページ**（フルビューポート高さ ×6セクション）+ 独自ローディング演出という構成。

### 0. 初回ローディング演出（`TerminalLoader`）
- 初回訪問時（`sessionStorage` に未記録の場合）のみ全画面表示。ナビからの「▸ Terminal」ボタンで再生も可能。
- 疑似ターミナルが実際のブラウザ/端末情報（画面解像度、タイムゾーン、GPU、回線速度、DNS/TTFB等のNavigation Timing、Feature detection 7項目）を「スキャン」するふりをして表示 → 実データなのでリロードごとに変化する。
- 締めに「brew --analyze」として、現在時刻に応じた抽出パラメータ（湯温・挽き目・比率）とおすすめドリンクを擬似生成して表示。
- `prefers-reduced-motion` 環境では即スキップ。「skip →」ボタンで途中離脱可能。

## 4. ビジュアル背景演出

- **`FaultyTerminalBg`**: ReactBits由来のWebGL（ogl）背景。CRT/ターミナルのようなグリッチ・走査線表現を全画面固定(fixed)で常時レンダリング。アンバー(#D4A017)にtint。
- 端末性能を`detectQuality()`で判定（dpr/CPUコア数/メモリ/GPU名等）し、high/mid/lowでdprと目標FPS・曲率パラメータを段階調整。`prefers-reduced-motion`時は静止1フレームのみ。
- 各セクション（Hero以外）はテキスト可読性のため背景に暗幕（radial-gradientのスクリム）を重ねている。
- 見出し等の一部テキストに「Decrypt」（文字化け→正解文字へ収束するタイプライター風演出）、価格に「CountUp」演出。

## 5. デザイントークン（正本: `design-system/MASTER.md`）

### カラー — 公開サイトは「ウォームアンバー」（管理画面はクールグレーで別パレット、混在させない）

| トークン | HEX/値 | 用途 |
|---|---|---|
| `--bg` | `#080600` | 背景 |
| `--bg2` | `#0f0d00` | 背景2 |
| `--surface` | `#1c1900` | カード等 |
| `--amber` | `#D4A017` | アクセント・リンク |
| `--amber2` | `#A37C18` | サブアクセント（AA対応済み） |
| `--amber3` | `#4A3808` | 深いアクセント |
| `--cream` | `#E8E0D0` | 本文テキスト |
| `--dim` | `rgba(232,224,208,0.45)` | 抑えたテキスト |
| `--faint` | `rgba(232,224,208,0.14)` | ボーダー/罫線 |

### タイポグラフィ

| 役割 | フォント | 備考 |
|---|---|---|
| 見出し/セリフ | Cormorant Garamond | ウェイト300/400、Hero・メニュー品名 |
| 本文/日本語 | IBM Plex Sans JP | ウェイト200/300/400（**本文200は薄すぎ注意**とMASTER.mdに明記） |
| モノスペース | IBM Plex Mono | ターミナル演出・価格・英字キャプション |

- 流体サイズは`clamp()`を多用。
- 本文は最低weight 300以上、重要な小文字はweight 400以上を推奨（現行の200はコントラスト面で要注意との既知課題）。

### モーション原則
- `prefers-reduced-motion`をCSS・JS両方で必ず尊重（既存の強み、崩さないこと）
- マイクロインタラクション150–300ms、Hero/リビール演出は1.3秒以内
- 1画面につき主要アニメーションは1〜2要素まで。常時稼働のフルスクリーンcanvas演出をこれ以上増やさない

### 非交渉ルール（抜粋）
- コントラスト比: 本文4.5:1以上
- すべてのインタラクティブ要素にフォーカスリング必須
- タッチターゲット44px以上
- 1画面につき主要CTAは1つ
- 2パレット（公開=アンバー／管理=クールグレー）を統一しない

## 6. 技術スタック・レンダリング方式

- **フレームワーク**: Next.js 16（App Router）+ React 19、Vercelホスティング
- **トップページの実装**: `page.tsx`（サーバーコンポーネント、メニュー/Instagramデータをサーバーでfetch）→ `HomeClient.tsx`（クライアントコンポーネント、演出制御）
- **アニメーション基盤**: GSAP + Lenis（スムーススクロール）+ 自作canvas / ReactBits由来コンポーネント
- **データソース**: メニューはDynamoDB管理（フォールバック値あり）、Instagram投稿はInstagram Graph API（月次トークン自動更新）
- **アクセシビリティ**: 現状 Lighthouse A11y 91 / Best Practices 100 / SEO 100（前回監査時点）
- **フォント**: next/font/google経由（Cormorant Garamond, IBM Plex Mono/Sans JP/Serif）、`display: swap`

## 7. 既知の課題・制約（デザイン変更時に考慮すべき事項）

1. **パフォーマンス**: 前回Lighthouse監査でPerformanceスコア49（モバイル）。以降WebGL背景の適応品質調整等で軽量化を実施したが、再計測は未実施。**演出の重さは既知のボトルネック**。
2. **コンバージョン導線の欠落**: オンラインショップへの導線がトップページ本文には一切なく、ナビの小さな「shop」テキストリンクのみ。せっかくの実装済みEC機能がトップから伝わらない。
   - ※ **2026-07-26 時点、オンライン決済は意図的に停止中**（AWS 移行 Phase 0・`docs/aws-migration-feasibility.md`）。`/shop` の閲覧・ブレンドづくりは通常どおり動くが、購入ボタンは停止表示になっている。トップページには停止表示を出さない方針。導線を設計する際は、再開後の姿を前提にしつつ停止中の見え方も考慮する。
3. **CTAが実質ゼロ**: Hero〜Contactまで、明確な行動喚起（購入・予約・フォロー等）を促すボタンがほぼない。デザイン原則上も「1画面1主要CTA」を推奨しているが現状は情報提示のみ。
4. **初回ローディング演出のコスト**: 毎初回訪問で数秒間のターミナルブート演出が入る（スキップ可）。ブランド体験としては強いが、直帰率・離脱への影響は未計測。
5. **決めていること（変更対象外にしたい/慎重に扱いたい部分）**:
   - ウォームアンバー×ダークのカラーパレット自体は意図的に確定済み（管理画面との使い分けも含め）
   - ターミナル/CLIモチーフ、マスコット「シコうさ」、`prefers-reduced-motion`対応は既存の強みとして維持したい
